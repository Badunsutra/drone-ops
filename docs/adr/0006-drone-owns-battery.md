# ADR 0006: DroneActor owns battery state

## Статус

Принято.

## Контекст

Если отдельный `BatteryManagerActor` принимает решения на основании состояния `DroneActor`, возникает лишний `ask`, stale state и нарушение принципа единого владельца состояния.

## Решение

`DroneActor` является единственным владельцем `BatteryLevel` и сам принимает решение о необходимости зарядки.

`ChargingCoordinatorActor` занимается только очередью зарядки и назначением станции.

## Следствия

- Меньше гонок состояния.
- Меньше request-reply взаимодействия.
- Поведение дрона становится локальной state machine.
- Логика батареи легче тестируется в чистом simulation layer.
